**Extensions** are [WASM plugins](../../../wasm/docs/index.mdx) that extend moon with functionality
that doesn't belong to a [toolchain](./toolchain.mdx) or a [task](./task.mdx). They're the general
purpose escape hatch of the plugin system: an extension can be invoked directly from the command
line as a one-off utility, or it can hook into moon's internals to shape the project graph, augment
commands before they execute, and participate in workspace and project syncing.

Because extensions are WASM, they run in a sandbox with whitelisted file system access, receive only
the information moon explicitly passes them, and are portable across every platform moon supports.

## Key characteristics

- **Sandboxed** - Executed as WASM with whitelisted access to the file system and a controlled view
  of the workspace.
- **Configuration driven** - Registered by a unique identifier in
  [`.moon/extensions.config`](#configuration), alongside any settings the plugin declares.
- **Distributable** - Sourced from a [plugin locator](../../../wasm/docs/plugin-locators.mdx),
  so they can be published to GitHub releases or an OCI registry, served from a URL, or live on the
  local file system.
- **Self describing** - Each plugin reports its own name, description, and version, and may declare
  a JSON schema for its settings.
- **Optional hooks** - A plugin implements only the functions it needs; moon skips the rest.

## Core features

### Direct execution

An extension that implements `execute_extension` can be run on demand with
[`moon ext`](../commands/ext.mdx), which loads the plugin and forwards every argument after `--` to it.
This is the model used by moon's built-in extensions, and is well suited to one-off utilities such
as downloading a file, unpacking an archive, or migrating configuration from another task runner.

```shell
$ moon ext unpack -- --src ./archive.tar.gz --dest ./out
```

### Project graph extension

During project graph construction, extensions implementing `extend_project_graph` are given the
ID and source of every project discovered through [`.moon/workspace.config`](./workspace.mdx). For
each of those projects, they can return an alias, implicit dependencies, and tasks, typically
extracted from a manifest file that moon doesn't understand natively. They can also return a list
of input files that were read, so that changes to those files invalidate the project graph cache.

Extensions can only extend projects that moon has already discovered; they can't add new projects to
the graph.

### Command augmentation

Before a process runs, extensions can rewrite it:

- `extend_command` - Applies to any command moon executes.
- `extend_task_command` - Applies to a [task](./task.mdx) that runs a command.
- `extend_task_script` - Applies to a task that runs a script.

Each hook can replace the command, modify its arguments, add or remove environment variables, and
contribute additional `PATH` lookup paths, which makes it possible to wrap tasks in a runner or
profiler without editing every task definition.

### Workspace and project syncing

Extensions implementing `sync_workspace` or `sync_project` run as part of moon's
[sync actions](./action.mdx), alongside the equivalent toolchain hooks. Both return the list of files
they changed, so syncing stays incremental and the results can be reported to the user. See
[`moon sync`](../commands/sync.mdx).

## Built-in extensions

moon ships with the following extensions, and knows where to find their plugins, so registering them
only requires their ID. Refer to each extension's page for its arguments and behavior.

| Extension                                                | ID                  | Description                                            |
| -------------------------------------------------------- | ------------------- | ------------------------------------------------------ |
| [Download](../extensions/download.mdx)                   | `download`          | Download a file from a URL into the workspace          |
| [Migrate Nx](../extensions/migrate-nx.mdx)               | `migrate-nx`        | Migrate an Nx repository's configuration to moon       |
| [Migrate Turborepo](../extensions/migrate-turborepo.mdx) | `migrate-turborepo` | Migrate a Turborepo repository's configuration to moon |
| [Unpack](../extensions/unpack.mdx)                       | `unpack`            | Unpack a local or remote archive into a directory      |

Built-in extensions still need to be configured before they can be executed with
[`moon ext`](../commands/ext.mdx), which only loads extensions that exist in
[`.moon/extensions.config`](#configuration). However,
[`moon extension add`](../commands/extension/add.mdx) and
[`moon extension info`](../commands/extension/info.mdx) accept these identifiers without a plugin
locator.

```shell
# Register the built-in extension, then execute it
$ moon extension add unpack
$ moon ext unpack -- --src ./archive.zip --dest ./out
```

## Configuration

Extensions are configured through `.moon/extensions.config`, where each top-level key is the unique
identifier the extension will be referenced by. The [`plugin`](/moon/api/ExtensionPluginConfig#plugin) setting is the locator moon uses to
find and download the WASM file, and every other key is arbitrary configuration passed through to
the plugin itself.

<ConfigTabs
  file=".moon/extensions"
  config={{
    unpack: {},
    "my-extension": {
      plugin: "github://organization/repository/my_extension",
      someSetting: true,
    },
  }}
/>

The `plugin` setting can be omitted entirely for [built-in extensions](#built-in-extensions), as
moon knows where to find them. Configuration files can also be composed with the [`extends`](/moon/api/ExtensionsConfig#extends) setting,
which accepts a relative file path or a secure URL, and merges extensions by their identifier (see
[sharing configuration](../guides/sharing-config.mdx#merging)).

Extensions can be added and inspected from the command line, instead of editing the configuration
file by hand:

- [`moon extension add`](../commands/extension/add.mdx) - Register an extension and write it to
  `.moon/extensions.config`.
- [`moon extension info`](../commands/extension/info.mdx) - Print an extension's metadata, settings
  schema, and the plugin functions it implements.
- [`moon extension download`](../commands/extension/download.mdx) - Download and cache the WASM plugins
  for every configured extension, without executing them.

## Creating an extension

Extensions are built with the same tooling as every other moon plugin. Read the
[WASM plugin docs](../../../wasm/docs/index.mdx) first, as they cover how plugins work, the sandbox they run
in, the host functions available to them, and how to create, build, and publish a plugin crate. Then implement the [extension specific API functions](../../../wasm/docs/extension.mdx) required for your extension.
