The `download` extension downloads a file from a URL into the workspace. It's a small, portable
alternative to `curl` or `wget`, which aren't available on every machine (or behave differently
between operating systems), so it's handy for:

- Fetching binaries, fixtures, or data files in a one-off setup step.
- Writing setup scripts that work the same on macOS, Linux, and Windows.
- Pairing with the [`unpack`](./unpack.mdx) extension, which can download and extract an archive
  in one step.

## Prerequisites

- **Network access** - The file is downloaded by moon itself, so no other tools are required.
- **A destination inside the workspace** - The extension runs in a WASM sandbox, and can only
  write to [directories that moon exposes to it](../guides/wasm-plugins.mdx#virtual-paths), like
  the workspace root.

## Installation

The `download` extension is built into moon, so no [`plugin`](/moon/api/ExtensionPluginConfig#plugin)
locator is required. Register it by adding a `download` entry to
[`.moon/extensions.config`](<../(fundamentals)/extension.mdx>), or by running
[`moon extension add`](../commands/extension/add.mdx), which writes the entry for you.

```shell
$ moon extension add download
```

The extension has no settings. Without a `plugin` locator, moon uses the version of the extension
that it was released with. To use a different version, set the
[locator](../guides/wasm-plugins.mdx#plugin-locators) explicitly, for example
`registry://ghcr.io/moonrepo/download_extension:1.0.4`.

## Usage

Run the extension with [`moon ext`](../commands/ext.mdx), passing its arguments after a `--`
separator.

```shell
# Download into the current working directory
$ moon ext download -- --url https://github.com/moonrepo/proto/releases/latest/download/proto_cli-aarch64-apple-darwin.tar.xz

# Download into a specific directory, with a custom file name
$ moon ext download -- --url https://github.com/moonrepo/proto/releases/latest/download/proto_cli-aarch64-apple-darwin.tar.xz --dest ./temp --name proto.tar.xz
```

## Arguments

- `--url`, `-u` <TypeLabel type="string" /> - The URL of the file to download. Must start with
  `http://` or `https://`. Required.
- `--dest`, `-d` <TypeLabel type="string" /> - The directory to save the file in. Relative paths
  are resolved from the current working directory, while absolute paths must be within a directory
  that moon exposes to the extension. Defaults to the current working directory.
- `--name` <TypeLabel type="string" /> - The file name to save as. Defaults to the last segment of
  the URL's path, without the query string or fragment, so
  `https://example.com/app.zip?token=abc` is saved as `app.zip`.

## How it works

When executed, the extension:

1. Validates that `--url` starts with `http://` or `https://`.
2. Resolves the destination directory, and fails if the destination is an existing file.
3. Creates the destination directory if it doesn't exist.
4. Downloads the file on the host machine, through moon's HTTP client
   ([plugins can't make network requests on their own](../guides/wasm-plugins.mdx#downloading-files)).
   The response is streamed into the file, instead of being loaded into memory, and the download
   fails if the response isn't a `2xx` status.

## Caveats

- An existing file with the same name in the destination is overwritten.
- When the URL's path doesn't end in a file name, like `https://example.com/latest/`, pass
  `--name`.
- Archives are written as-is. Use the [`unpack`](./unpack.mdx) extension to extract them.
