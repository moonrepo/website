Run all build and test related [tasks](<../(fundamentals)/task.mdx>) for one or many projects. This is a convenience
command for verifying the current state of a project (or the entire workspace), without having to
know or type out every individual [`moon run`](./run.mdx) target.

Internally, `check` scans the requested project(s), collects every task marked with a `type` of
`build` or `test` (or inferred as such), and funnels them into the same
[action pipeline](./exec.mdx) used by [`moon run`](./run.mdx) and [`moon exec`](./exec.mdx) — meaning all the
options below (affected checks, caching, parallelism, and so on) behave identically to those
commands. The pipeline is always run with `--on-failure=bail`, so the first failing task stops the
remaining ones.

[Persistent tasks](<../(fundamentals)/task.mdx#persistent>) never complete, and neither would the
check, so persistent build or test tasks are only ran when another task depends on them. And when
the selected projects have no build or test tasks at all, `moon check` prints a warning and exits
with code `1`, instead of running nothing.

Projects can be selected in one of three mutually exclusive ways: by passing explicit project IDs
as arguments, with `--all` to check every project in the workspace, or with `--closest` to check
only the project closest to the current working directory. When none of these are provided and the
terminal is interactive, `moon check` prompts with a multi-select list of every project in the
workspace; in a non-interactive environment (CI, scripts, pipes) omitting all three will error.

```shell
# Check a project by ID
$ moon check app

# Check multiple projects by ID
$ moon check client server

# Check the closest project from the current working directory
$ moon check --closest

# Check every project in the workspace (can be costly)
$ moon check --all

# Check only projects affected by changed files
$ moon check --all --affected
```

This command can also be run with the `moon c` alias.

## Arguments

- `[IDS...]` - List of explicit project IDs to check, as defined in
  [`projects`](<../(fundamentals)/workspace.mdx#project-discovery>). Mutually exclusive with `--all` and `--closest`.

## Options

### Projects

- `--all` - Check every project in the workspace. Mutually exclusive with `[IDS]` and `--closest`.
- `--closest` - Check the project closest to the current working directory, determined by
  traversing up from the working directory until a project boundary is found. Mutually exclusive
  with `[IDS]` and `--all`.

### Affected

- `--affected` <TypeLabel type="boolean | string" /> - Only run tasks if
  [affected](../advanced/affected.mdx) by changed files, or by an affected dependency task (see
  `--affected-depth`). When passed without
  a value, changed files are detected from the local working tree; a string value further filters
  affected checks. Can also be set via the `MOON_AFFECTED` environment variable.
- `--base` <TypeLabel type="string" /> - Base branch, commit, or revision to compare against when
  determining changed files. Can also be set via the `MOON_BASE` environment variable.
- `--head` <TypeLabel type="string" /> - Current branch, commit, or revision to compare with when
  determining changed files. Defaults to the working tree. Can also be set via the `MOON_HEAD`
  environment variable.
- `-d`, `--affected-depth` <TypeLabel type="none | direct | deep | number" /> - How far affected
  state propagates from an affected task to the tasks that depend on it, in hops. This only changes
  which of the selected tasks count as affected, and never adds tasks. Requires `--affected` to also
  be passed. Defaults to `deep`. Can also be set via the `MOON_AFFECTED_DEPTH` environment variable.
  See [tracking depth](../advanced/affected.mdx#tracking-depth) for more information.
- `--status` <TypeLabel type="added | all | deleted | modified | staged | unstaged | untracked" /> -
  Filter changed files based on one or more changed statuses. Requires `--affected` to also be
  passed. Defaults to `all`.
- `--stdin` - Accept a list of changed files from stdin, instead of querying the VCS for them.
  Requires `--affected` to also be passed.

### Graph

- `--dependents` <TypeLabel type="none | direct | deep | number" /> - Also run the tasks that
  depend on the selected targets, up to this many hops away. Added tasks are still filtered by
  `--affected` and `--query`. Defaults to `none`.
- `--no-dependencies` - Don't run dependency tasks that weren't selected themselves, except for
  [cleanup dependencies](<../(fundamentals)/task.mdx#dependency-types>). The order between the
  tasks that are run is still honored.

### Parallelism

- `--job` <TypeLabel type="number" /> - Index (zero-based) of the current job, used to partition
  and distribute targets across multiple machines or processes. Can also be set via the `MOON_JOB`
  environment variable.
- `--job-total` <TypeLabel type="number" /> - Total number of jobs being run, used alongside
  `--job` to determine this job's partition of targets. Can also be set via the `MOON_JOB_TOTAL`
  environment variable.

### Workflow

- `-f`, `--force` - Force run and bypass the cache, ignore changed files, and skip affected checks
  (tasks still run even when unaffected). Can also be set via the `MOON_FORCE` environment
  variable.
- `-i`, `--interactive` - Run the pipeline and its tasks interactively, allowing tasks to receive
  input from the terminal.
- `--no-actions` - Run the pipeline without executing sync and setup related actions (toolchain
  installation, project syncing, etc), running only the requested tasks. Can also be set via the
  `MOON_NO_ACTIONS` environment variable.
- `--output-style` <TypeLabel type="buffer | buffer-only-failure | hash | none | stream" /> -
  Control how output is displayed for _all_ tasks, overriding their
  [`options.outputStyle`](/moon/api/TaskOptionsConfig#outputstyle) setting, including for primary
  targets. See [output style](<../(fundamentals)/task.mdx#output-style>) for more information.
- `-p`, `--plan` <TypeLabel type="string" /> - Relative path to an
  [execution plan](../guides/exec-plan.mdx) (JSON) used to further customize the action graph and
  pipeline for this run. Can also be set via the
  `MOON_EXEC_PLAN` environment variable.
- `-s`, `--summary` <TypeLabel type="boolean | string" /> - Print a summary of all actions that were
  ran in the pipeline. Accepts `none`, `minimal`, `normal` (default when the flag is passed without
  a value), or `detailed`. Can also be set via the `MOON_SUMMARY` environment variable.
