Run tasks in a continuous integration (CI) environment, with sane defaults tailored for that
context. Like [`moon check`](./check.mdx), this is a thin wrapper around the same
[action pipeline](./exec.mdx) used by [`moon run`](./run.mdx) and [`moon exec`](./exec.mdx), but it pre-fills a
handful of options so that a single `moon ci` invocation is typically all a CI pipeline needs.

Compared to running tasks directly, `moon ci`:

- Always detects affected tasks by comparing changed files against a base revision — this cannot be
  disabled, though how the comparison is made can still be customized with the affected options
  below. When running inside a supported CI provider, the base and head revisions (and whether the
  build is for a pull request) are automatically extracted from the CI environment if `--base` and
  `--head` aren't explicitly provided. See [comparing revisions](../guides/ci.mdx#comparing-revisions)
  for the full resolution order.
- Always respects each task's [`options.runInCI`](/moon/api/TaskOptionsConfig#runinci) setting, so
  tasks that [don't run in CI](../guides/ci.mdx#configuring-tasks-to-run) never run.
- Forces the pipeline into CI mode (as if `--ci` were passed to [`moon exec`](./exec.mdx)), which
  affects how the console renders output and how other moon features detect a CI environment.
- Continues running remaining tasks after a failure, instead of bailing on the first one, so a
  single broken task doesn't hide the results of the others.
- Catches regressions in the tasks that depend on what changed. Affected state propagates from an
  affected task to its dependents (up to `--affected-depth`), and as every task in the workspace is
  a candidate when no targets are passed, those dependents run too. When passing explicit targets,
  add `--dependents`, like `--dependents direct`, to also run the tasks that depend on them.
- Prints a detailed summary of the pipeline by default (unless `--summary` is passed explicitly), so
  CI logs always contain a full breakdown of what ran.
- Writes its [run report](../guides/ci.mdx#reporting-run-results) to `.moon/cache/ciReport.json`,
  instead of the `runReport.json` file used by other commands.

When no explicit targets are passed and no `--plan` is provided, every task in the workspace is
queued up as a candidate, and the affected and [`options.runInCI`](/moon/api/TaskOptionsConfig#runinci) checks above determine which of them
actually execute. Passing explicit targets narrows this candidate list down first, but the same
affected and `runInCI` filtering is still applied on top.

[Persistent tasks](<../(fundamentals)/task.mdx#persistent>), like servers, never complete, so they'd
keep the CI pipeline running until it times out. They don't run in CI unless they enable
[`options.runInCI`](/moon/api/TaskOptionsConfig#runinci), and even then, `moon ci` only runs them when another task depends on them (like
an end-to-end test that [waits](<../(fundamentals)/task.mdx#dependency-types>) on a server), or when
they're explicitly passed as a target.

```shell
# Run every affected, CI-enabled task in the workspace
$ moon ci

# Run specific targets, still filtered by affected status and runInCI
$ moon ci :build :lint

# Compare against an explicit base and head revision
$ moon ci --base main --head HEAD

# Shard the run across 2 parallel CI jobs
$ moon ci --job 0 --job-total 2

# Keep passing tasks quiet, and only print the output of failing tasks
$ moon ci --output-style buffer-only-failure
```

See the [continuous integration guide](../guides/ci.mdx) for a deeper walkthrough of wiring `moon ci`
into common CI providers, including
[sharding examples](../guides/ci.mdx#parallelizing-tasks).

## Arguments

- `[TARGETS...]` - List of explicit task [targets](<../(fundamentals)/target.mdx>) to run. When omitted, every task in
  the workspace is considered, subject to affected and [`options.runInCI`](/moon/api/TaskOptionsConfig#runinci) filtering.

## Options

### Affected

- `--base` <TypeLabel type="string" /> - Base branch, commit, or revision to compare against when
  determining changed files. When running in a supported CI provider, this is automatically derived
  from the CI environment (for example, the pull request's base branch) if not provided. Can also be
  set via the `MOON_BASE` environment variable, which takes precedence over this option when it isn't empty.
- `--head` <TypeLabel type="string" /> - Current branch, commit, or revision to compare with when
  determining changed files. When running in a supported CI provider, this is automatically derived
  from the CI environment if not provided; otherwise defaults to the working tree. Can also be set
  via the `MOON_HEAD` environment variable, which takes precedence over this option when it isn't empty.
- `-d`, `--affected-depth` <TypeLabel type="none | direct | deep | number" /> - How far affected
  state propagates from an affected task to the tasks that depend on it, in hops. This only changes
  which of the candidate tasks count as affected, and never adds tasks. Defaults to `deep`. Can also
  be set via the `MOON_AFFECTED_DEPTH` environment variable. See
  [tracking depth](../advanced/affected.mdx#tracking-depth) for more information.
- `--status` <TypeLabel type="added | all | deleted | modified | staged | unstaged | untracked" /> -
  Filter changed files based on one or more changed statuses. Defaults to `all`.
- `--stdin` - Accept a list of changed files from stdin, instead of querying the VCS for them.

### Graph

- `--dependents` <TypeLabel type="none | direct | deep | number" /> - Also run the tasks that
  depend on the candidate targets, up to this many hops away. Added tasks are still filtered by
  affected status and [`options.runInCI`](/moon/api/TaskOptionsConfig#runinci). Defaults to `none`.
- `--no-dependencies` - Don't run dependency tasks that weren't selected themselves, except for
  [cleanup dependencies](<../(fundamentals)/task.mdx#dependency-types>). The order between the
  tasks that are run is still honored.

### Parallelism

- `--job` <TypeLabel type="number" /> - Index (zero-based) of the current job, used to shard targets
  across multiple parallel CI jobs or machines. Must be paired with `--job-total`. Can also be set
  via the `MOON_JOB` environment variable.
- `--job-total` <TypeLabel type="number" /> - Total number of jobs being run, used alongside `--job`
  to determine this job's partition of targets. Can also be set via the `MOON_JOB_TOTAL` environment
  variable.

### Workflow

- `-f`, `--force` - Force run and bypass the cache, ignore changed files, and skip affected checks
  (tasks still run even when unaffected, though affected files are still tracked). Can also be set
  via the `MOON_FORCE` environment variable.
- `-i`, `--interactive` - Run the pipeline and its tasks interactively, allowing tasks to receive
  input from the terminal.
- `--no-actions` - Run the pipeline without executing sync and setup related actions (toolchain
  installation, project syncing, etc), running only the requested tasks. Can also be set via the
  `MOON_NO_ACTIONS` environment variable.
- `--output-style` <TypeLabel type="buffer | buffer-only-failure | hash | none | stream" /> -
  Control how output is displayed for _all_ tasks, overriding their
  [`options.outputStyle`](/moon/api/TaskOptionsConfig#outputstyle) setting, including for primary
  targets. See [output style](<../(fundamentals)/task.mdx#output-style>) for more information.
- `-p`, `--plan` <TypeLabel type="string" /> - Relative path to an
  [execution plan](../guides/exec-plan.mdx) (JSON) used to further customize the action graph and
  pipeline for this run. The plan should define its own targets, as `moon ci` only falls back to
  every task in the workspace when no plan is provided. Can also be set via the `MOON_EXEC_PLAN`
  environment variable.
- `-s`, `--summary` <TypeLabel type="boolean | string" /> - Print a summary of all actions that were
  ran in the pipeline. Accepts `none`, `minimal`, `normal`, or `detailed`. When passed without a
  value, defaults to `normal`; when omitted entirely, defaults to `detailed` (unlike
  [`moon run`](./run.mdx) and [`moon exec`](./exec.mdx), which default to `normal`). Can also be set via the
  `MOON_SUMMARY` environment variable.
