Generates a multi-stage, production-oriented `Dockerfile` for a project, pre-wired to run the other
[`moon docker`](../docker.mdx) commands in the correct order. The file is split into the following
stages, and the [Docker guide](../../guides/docker.mdx#generating-a-dockerfile) walks through an
example of the output:

- `base` - Installs moon into the chosen base image, which requires Bash and `curl`.
- `skeleton` - Copies in the repository and runs [`moon docker scaffold`](./scaffold.mdx) for the
  project.
- `build` - Copies the scaffolded skeletons, installs toolchains and dependencies with
  [`moon docker setup`](./setup.mdx), optionally runs a build task, and optionally strips
  development dependencies with [`moon docker prune`](./prune.mdx).
- `start` - Runs the project with a start task, typically an HTTP server or a binary. This stage is
  omitted when no start task is chosen.

Each value is resolved from its command line option first, then from the project's or workspace's
[`docker.file`](/moon/api/DockerConfig#file) settings (see
[configuring generation](../../guides/docker.mdx#configuring-generation)). When no image is
configured, the image of the first of the project's toolchains that provides one (via its
`defineDockerMetadata` hook) is used, and otherwise `scratch`. Unless `--defaults` is passed, moon
prompts for the image, and for which of the project's tasks to use for the build and start steps
(an option to select "none" is always available).

The command writes the file to the project's root, defaulting to a file named `Dockerfile`, or a
custom `[DEST]` path relative from the project root. It does not build or run Docker itself; it
only generates the file.

```shell
# Interactively prompt for a Docker image and build/start tasks
$ moon docker file app

# Skip prompts and use configured or discovered defaults
$ moon docker file app --defaults

# Write to a custom location and use an explicit base image
$ moon docker file app ./docker/Dockerfile --image node:20-slim
```

## Arguments

- `<ID>` - ID of the [project](<../../(fundamentals)/project.mdx>) to generate a `Dockerfile` for.
- `[DEST]` - Destination path to write the file to, relative from the project root. Defaults to
  `Dockerfile`.

## Options

- `--defaults` - Use default options derived from configuration instead of prompting for the image
  and build/start tasks in the terminal. When a build or start task isn't configured, that step is
  left out.
- `--build-task` <TypeLabel type="string" /> - ID of a task within the project to run in the
  `build` stage. When omitted, falls back to the project's or workspace's
  [`docker.file.buildTask`](/moon/api/DockerFileConfig#buildtask) setting, or prompts for a task (or none) interactively. When no build
  task is used, the build step is skipped entirely.
- `--image` <TypeLabel type="string" /> - Base Docker image to use for every stage. When
  omitted, falls back to the project's or workspace's [`docker.file.image`](/moon/api/DockerFileConfig#image) setting, then to an
  image derived from the project's toolchain, then to `scratch`.
- `--no-prune` - Do not run [`moon docker prune`](./prune.mdx) in the `build` stage. Overrides the
  project's or workspace's [`docker.file.runPrune`](/moon/api/DockerFileConfig#runprune) setting, which defaults to `true`.
- `--no-setup` - Do not run [`moon docker setup`](./setup.mdx) in the `build` stage. Overrides the
  project's or workspace's [`docker.file.runSetup`](/moon/api/DockerFileConfig#runsetup) setting, which defaults to `true`.
- `--no-toolchain` - Do not install moon's toolchain into the image, and instead rely on system
  binaries that already exist in the base image, by setting `MOON_TOOLCHAIN_FORCE_GLOBALS` in the
  `base` stage. This is implied when the image name contains `alpine`. See
  [using system binaries](../../guides/docker.mdx#using-system-binaries).
- `--start-task` <TypeLabel type="string" /> - ID of a task within the project to run via the
  `CMD` instruction in the `start` stage. When omitted, falls back to the project's or
  workspace's [`docker.file.startTask`](/moon/api/DockerFileConfig#starttask) setting, or prompts for a task (or none) interactively.
  When no start task is used, the `start` stage is omitted from the file.
- `--template` <TypeLabel type="string" /> - Path to a
  [custom Tera template](../../guides/docker.mdx#custom-templates), relative from the workspace root, used to render the `Dockerfile` instead of moon's
  built-in template. Falls back to the project's or workspace's [`docker.file.template`](/moon/api/DockerFileConfig#template) setting.
  Errors if the resolved path does not exist.
