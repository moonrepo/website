---
title: moon daemon start
---

Start the [daemon](../daemon.mdx) if it's not already running (alias: `startup`).

If a daemon for this workspace is already accepting connections, its existing process ID is reused and reported back — this command never spawns a second, competing daemon. Otherwise, a new daemon process is spawned detached from the current terminal (as `moon daemon server`, logging at trace level to its log file), and the command waits, polling for readiness, until it either starts accepting connections or a startup timeout is reached, in which case the command fails. Concurrent starts are coordinated through on-disk and in-process locks, so if another `moon` command is starting the daemon at the same time (or another CLI process entirely), this command waits for that spawn to finish instead of racing it.

You typically don't need to run this manually: once the daemon is enabled, commands that run the action pipeline (like [`moon run`](../run.mdx) and [`moon ci`](../ci.mdx)) start it automatically on first use. Running `moon daemon start` by hand is mostly useful for warming the daemon up ahead of time, like right after enabling the setting. Don't start it in CI: the daemon is never used in CI environments or one-off Docker containers, as its background work may not finish before the machine or container is torn down.

The [`unstable_daemon`](/moon/api/WorkspaceConfig#daemon) setting must be enabled in [`.moon/workspace.config`](<../../(fundamentals)/workspace.mdx>) (or via the `MOON_DAEMON` environment variable) for this to do anything; otherwise a warning is shown and the command exits without starting a process.

```shell
$ moon daemon start
```
