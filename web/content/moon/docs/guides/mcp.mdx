[Model Context Protocol](https://modelcontextprotocol.io) (MCP) is an open standard that enables AI
models to interact with external tools and services through a unified interface. The moon CLI
contains an MCP server, started with [`moon mcp`](../commands/mcp.mdx), that you can register with
your code editor or AI agent, so that LLMs can query and operate on your moon workspace directly,
instead of guessing from configuration files.

<Callout>
  The MCP server implements the stateless MCP `2026-07-28` protocol, so your
  client (code editor, AI agent, etc) must support this protocol version. Older
  protocol versions (`2025-11-25` and below) and the `initialize` handshake are
  not supported.
</Callout>

## How it works

The server communicates over stdio, so it's never ran manually. Instead, your client spawns
`moon mcp` as a subprocess, which requires the `moon` binary to be available on the client's `PATH`.

When started, the server loads the project and task graph of the workspace once, and answers every
request from it. If you change configuration while the server is running, restart the server from
your client to pick up the changes.

The workspace is located by searching upwards from the server's working directory for a `.moon`
directory, which works when the client starts the server within your repository. When it doesn't,
like with a global configuration, set the `MOON_WORKSPACE_ROOT` environment variable to the absolute
path of the workspace.

## Setup

Every client registers the server the same way: a command of `moon`, with arguments of `["mcp"]`.
The examples below use a client's project-level configuration where it has one, which you can
commit so that your team shares the setup. A global configuration isn't tied to a repository, so it
also needs the `MOON_WORKSPACE_ROOT` environment variable, as described in
[how it works](#how-it-works). Most clients don't document which directory they start servers in,
so if the server can't find your workspace, set `MOON_WORKSPACE_ROOT` for project-level
configuration too.

### Amp

To use [MCP servers in Amp](https://ampcode.com/docs/customize/mcp), add the server under
`amp.mcpServers` in a `.amp/settings.json` file in your project, or in
`~/.config/amp/settings.json` globally.

```json title=".amp/settings.json"
{
  "amp.mcpServers": {
    "moon": {
      "command": "moon",
      "args": ["mcp"]
    }
  }
}
```

Servers in a workspace's settings must be approved before they run, with `amp mcp approve moon`.
Run `amp mcp doctor` to check the server's status.

### Claude Code

To use [MCP servers in Claude Code](https://code.claude.com/docs/en/mcp), run the following command
in your terminal. With the `project` scope, the server is written to an `.mcp.json` file at the root
of your project, so it can be shared with your team.

```shell
# Register the server for everyone in the project
$ claude mcp add moon -s project -- moon mcp

# Or register it for yourself, in every project
$ claude mcp add moon -s user -e MOON_WORKSPACE_ROOT=/absolute/path/to/workspace -- moon mcp
```

Or create the `.mcp.json` file in your project directory manually:

```json title=".mcp.json"
{
  "mcpServers": {
    "moon": {
      "command": "moon",
      "args": ["mcp"]
    }
  }
}
```

Claude Code asks you to approve the servers in a project's `.mcp.json` before using them.

### Claude Desktop

To use [local MCP servers in Claude Desktop](https://modelcontextprotocol.io/docs/develop/connect-local-servers),
open **Settings > Developer > Edit Config**, which opens the `claude_desktop_config.json` file
(`~/Library/Application Support/Claude` on macOS, and `%APPDATA%\Claude` on Windows). Claude
Desktop has no project-level configuration, so `MOON_WORKSPACE_ROOT` is required.

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "moon": {
      "command": "moon",
      "args": ["mcp"],
      "env": {
        "MOON_WORKSPACE_ROOT": "/absolute/path/to/workspace"
      }
    }
  }
}
```

Fully quit and restart Claude Desktop afterwards, so that it starts the server.

### Codex

To use [MCP servers in Codex](https://developers.openai.com/codex/mcp), run the following command,
which adds the server to `~/.codex/config.toml`. This file is shared by the Codex CLI, the IDE
extension, and the ChatGPT desktop app.

```shell
$ codex mcp add moon --env MOON_WORKSPACE_ROOT=/absolute/path/to/workspace -- moon mcp
```

Or add it to the file manually. Servers can also be added to a `.codex/config.toml` file in a
project, which Codex only loads for trusted projects.

```toml title="~/.codex/config.toml"
[mcp_servers.moon]
command = "moon"
args = ["mcp"]

[mcp_servers.moon.env]
MOON_WORKSPACE_ROOT = "/absolute/path/to/workspace"
```

Run `/mcp` in Codex, or `codex mcp list`, to check that the server is registered.

### Continue

To use [MCP servers in Continue](https://docs.continue.dev/customize/deep-dives/mcp), create a
`.continue/mcpServers/moon.yaml` file in your project. MCP tools are only available in Continue's
agent mode.

```yaml title=".continue/mcpServers/moon.yaml"
name: moon
version: 0.0.1
schema: v1
mcpServers:
  - name: moon
    type: stdio
    command: moon
    args:
      - mcp
```

your project directory, or `~/.cursor/mcp.json` globally, with the following content. As the global
configuration isn't tied to a project, it requires `MOON_WORKSPACE_ROOT`.

```json title=".cursor/mcp.json"

  "mcpServers": {
    "moon": {
      "type": "stdio",

```

Once configured, enable the server from **Customize** in Cursor's sidebar. Cursor asks for
approval before running MCP tools by default.

the global `mcp_config.json` file (`~/.config/devin` on macOS and Linux, and `%APPDATA%\devin` on
Windows). Devin Desktop has no project-level configuration, so `MOON_WORKSPACE_ROOT` is required.

```json title="mcp_config.json"

```

Once configured, make sure the server is toggled on in the MCPs section of the Cascade panel.

### Gemini CLI

To use [MCP servers in Gemini CLI](https://geminicli.com/docs/tools/mcp-server/), run the
following command, which adds the server to a `.gemini/settings.json` file in your project. Pass
`-s user` to add it to `~/.gemini/settings.json` instead.

```shell
$ gemini mcp add moon moon mcp
```

Or create the `.gemini/settings.json` file manually:

```json title=".gemini/settings.json"
{
  "mcpServers": {
    "moon": {
      "command": "moon",
      "args": ["mcp"]
    }
  }
}
```

Gemini CLI only starts servers in trusted folders, so trust your project with `gemini trust`, then
run `/mcp` to check the server's status.

### GitHub Copilot CLI

To use [MCP servers in GitHub Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers),
create a `.github/mcp.json` file in your repository. Copilot CLI also reads servers from a
`.mcp.json` file in the repository, and from `~/.copilot/mcp-config.json` globally, which is where
`copilot mcp add moon -- moon mcp` writes to.

```json title=".github/mcp.json"
{
  "mcpServers": {
    "moon": {
      "type": "local",
      "command": "moon",
      "args": ["mcp"],
      "tools": ["*"]
    }
  }
}
```

Copilot CLI only loads a repository's servers once you've confirmed that you trust the folder. Run
`/mcp show moon` to check the server's status.

### Goose

To use [extensions in Goose](https://goose-docs.ai/docs/getting-started/using-extensions), run
`goose configure`, select **Add Extension > Command-line Extension**, and enter `moon mcp` as the
command. Or add it to the global `~/.config/goose/config.yaml` file manually. Goose has no
project-level configuration, so `MOON_WORKSPACE_ROOT` is required.

```yaml title="~/.config/goose/config.yaml"
extensions:
  moon:
    name: moon
    type: stdio
    cmd: moon
    args:
      - mcp
    enabled: true
    envs:
      MOON_WORKSPACE_ROOT: /absolute/path/to/workspace
    timeout: 300
```

### OpenCode

To use [MCP servers in OpenCode](https://opencode.ai/docs/mcp-servers/), add the server under `mcp`
in an `opencode.json` file in your project, or in `~/.config/opencode/opencode.json` globally.
Unlike most clients, the command and its arguments are a single list.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "moon": {
      "type": "local",
      "command": ["moon", "mcp"],
      "enabled": true
    }
  }
}
```

### VS Code

To use [MCP servers in VS Code](https://code.visualstudio.com/docs/agent-customization/mcp-servers),
create a `.vscode/mcp.json` file in your workspace with the following content. The server runs from
your workspace folder, so `MOON_WORKSPACE_ROOT` isn't needed.

```json title=".vscode/mcp.json"
{
  "servers": {
    "moon": {
      "type": "stdio",
      "command": "moon",
      "args": ["mcp"]
    }
  }
}
```

VS Code also supports the portable `mcpServers` format used by other clients, in a `.mcp.json`
file at the workspace root, or in `~/.copilot/mcp-config.json` globally. Its **MCP: Add Server**
command labels `.vscode/mcp.json` as deprecated in favor of these, but the file is still supported,
and its servers are forwarded to Copilot sessions.

Once configured, start a chat, and enable moon's tools with **Configure Tools** in the chat input,
or with **Chat: Open Customizations > Tools** for Copilot sessions.

### Zed

To use [MCP servers in Zed](https://zed.dev/docs/ai/mcp), add the server to a `.zed/settings.json`
file in your project directory, or to your global Zed settings, with the following content. The
global settings require `MOON_WORKSPACE_ROOT`.

```json title=".zed/settings.json"
{
  "context_servers": {
    "moon": {
      "command": "moon",
      "args": ["mcp"],
      "env": {}
    }
  }
}
```

Zed only applies a project's settings, and starts its MCP servers, once you
[trust the worktree](https://zed.dev/docs/worktree-trust). Once trusted, the server should be marked
as active in the MCP servers section of Zed's AI settings. Which tools the agent can use is
controlled by your agent profile, so make sure moon's tools are enabled in the profile you're
using.

### Other clients

Most other clients accept a similar configuration: a command of `moon`, arguments of `["mcp"]`, and
optionally a `MOON_WORKSPACE_ROOT` environment variable.

```json
{
  "mcpServers": {
    "moon": {
      "command": "moon",
      "args": ["mcp"],
      "env": {
        "MOON_WORKSPACE_ROOT": "/absolute/path/to/your/moon/workspace"
      }
    }
  }
}
```

## Available tools

The following tools are available in the moon MCP server, and can be executed by LLMs in agent mode.
Clients discover each tool's input schema automatically, so the inputs below are for reference.
Responses are pretty-printed JSON.

### Reading the workspace

These tools only read from the workspace graph, so they're safe to call repeatedly.

- `get_project` - Get a [project](<../(fundamentals)/project.mdx>) and its tasks by `id`. Set
  `include_dependencies` to also return the projects it depends on.
- `get_projects` - Get a summary of all projects.
- `get_task` - Get a [task](<../(fundamentals)/task.mdx>) by its fully-qualified `target`, like
  `app:build`. Set `include_dependencies` to also return the tasks it depends on.
- `get_tasks` - Get a summary of all tasks. Set `include_internal` to also return
  [internal](<../(fundamentals)/task.mdx#internal-only>) tasks.
- `get_template` - Get a [template](./codegen.mdx) by `id`, with its full variable schema (types,
  defaults, prompts, required flags, and enum values), and its
  [`extends`](/moon/api/TemplateConfig#extends) chain resolved. Internal variables are excluded.
- `get_templates` - List all templates with their id, title, and description. Pass `filter` to only
  return templates whose ID matches a case-insensitive regular expression.
- `get_changed_files` - Get changed files from version control. By default, only uncommitted
  changes are returned when running locally. Set `remote` to `true` to compare the `base` revision
  (defaults to [`vcs.defaultBranch`](/moon/api/VcsConfig#defaultbranch)) against the `head`
  revision (defaults to `HEAD`) instead, which is the default in CI and other remote environments.

### Changing the workspace

These tools write files, so your client may ask for confirmation before running them.

- `sync_projects` - Run the `SyncProject` action for each project in `ids`, or for all projects
  when `ids` is empty (like [`moon sync projects`](../commands/sync/projects.mdx)). Returns the
  actions that ran.
- `sync_workspace` - Run the `SyncWorkspace` action, which syncs workspace-level files, like code
  owners and VCS hooks, depending on what's configured. Unlike [`moon sync`](../commands/sync.mdx),
  projects aren't synced. Returns the actions that ran.
- `generate` - Generate code from a `template` into the `to` destination, by running
  [`moon generate`](../commands/generate.mdx). Pass template `variables` as an object, and set
  `dry_run` or `force` as needed. Returns whether it succeeded, and the error if it didn't.

<Callout>
  The [response
  shapes](https://github.com/moonrepo/moon/blob/master/packages/types/src/mcp.ts)
  for these tools are defined as TypeScript types in the
  [`@moonrepo/types`](https://www.npmjs.com/package/@moonrepo/types) package.
</Callout>

## Troubleshooting

If a tool isn't working as expected, write the server's logs to a file, and set the `MOON_DEBUG_MCP`
environment variable to also include logs from the underlying MCP libraries.

```json
{
  "mcpServers": {
    "moon": {
      "command": "moon",
      "args": ["mcp", "--log", "debug", "--log-file", "/tmp/moon-mcp.log"],
      "env": {
        "MOON_DEBUG_MCP": "true"
      }
    }
  }
}
```
