title: moon

[moon](https://moonrepo.dev/moon) is moonrepo's build system and repository management tool. It runs
the tasks of every project in your repository through a single, cached pipeline, in any language.
It's a [built-in tool](<../(fundamentals)/(plugin)/tool.mdx#built-in-tools>) with the `moon` ID,
so it works without configuring a plugin.

proto downloads the official release for your platform from GitHub. Installing moon with proto is
the easiest way to pin it per repository, so everyone, including CI, runs the same version. It
provides the `moon` and `moonx` [executables](<../(fundamentals)/(plugin)/tool.mdx#executables>):

- `moon` - The primary executable, and moon's full CLI.
- `moonx` - A shorthand for [`moon exec`](../../../moon/docs/commands/exec.mdx), so
  `moonx app:build` runs the same task as `moon exec app:build`. Only provided for moon v2 and
  later.

For other ways to install moon, see its [installation guide](../../../moon/docs/index.mdx).

## Prerequisites

- **Git** - Versions are listed from the tags of the
  [moonrepo/moon](https://github.com/moonrepo/moon) repository, with `git ls-remote`, so `git` must
  be on your `PATH` (see [requirements](../index.mdx#requirements)).
- **A supported platform** - moon is published for Linux (x64 and arm64), macOS (x64 and arm64),
  and Windows (x64). On Linux, proto downloads the GNU or musl build that matches your system. Other
  platforms, like Windows on arm64, fail with an unsupported platform error.

## Installation

Install moon with [`proto install`](../commands/install.mdx), and pin a version with
[`proto pin`](../commands/pin.mdx), or with the `--pin` option while installing:

```shell
# Install the detected version, or the latest when none is detected
$ proto install moon

# Install the newest 3.0 release, and pin it to the closest .prototools
$ proto install moon 3.0 --pin

# Pin a version without installing it
$ proto pin moon 3.0.0

# Install every pinned tool, including moon, after cloning
$ proto install
```

```toml title=".prototools"
moon = "3.0.0"
```

Besides versions and ranges, moon supports the `latest`
[alias](<../(fundamentals)/version-spec.mdx#built-in-aliases>), but not `canary`. An exact version
is the most reproducible for a tool that runs your whole pipeline, but any
[version specification](<../(fundamentals)/version-spec.mdx>) works, like `3` or `~3.0`.

moon has no version file of its own for proto to detect, so pin it in a
[`.prototools`](<../(fundamentals)/config.mdx>) at the root of your repository. proto doesn't read
moon's own [`versionConstraint`](/moon/api/WorkspaceConfig#versionconstraint) setting: it doesn't
select a version, but it does make moon fail when a version outside its range runs.

To upgrade, run [`moon upgrade`](../../../moon/docs/commands/upgrade.mdx). When moon is installed by
proto, it runs [`proto install moon latest --pin local`](../commands/install.mdx) for you, which
installs the newest release and pins it to the [`.prototools`](<../(fundamentals)/config.mdx>) in
the current directory. Unlike most tools' self-upgrade commands, proto doesn't
[block it](<../(fundamentals)/(plugin)/tool.mdx#running-tools>).

```shell
# Upgrade with moon, which defers to proto
$ moon upgrade

# Or upgrade with proto directly
$ proto install moon latest --pin
```

### Building from source

Pass `--build` to [`proto install`](../commands/install.mdx) to
[build moon from source](../guides/build-from-source.mdx), instead of downloading a prebuilt. It's
supported on the same platforms as the prebuilts. proto downloads the release's source archive from
GitHub, and compiles `moon` (and `moonx`, for v2 and later) with Cargo.

```shell
# Build moon from source, instead of downloading a prebuilt
$ proto install moon 3.0.0 --build
```

The build needs:

- Rust, with `cargo` on `PATH`.
- `protoc`, the Protocol Buffers compiler, for moon v2.2 and later.

Before building, proto offers to install the
[system dependencies](../guides/build-from-source.mdx#system-dependencies) that moon needs, which
are `protobuf-compiler` with apt, or `protobuf` with Homebrew, for `protoc`. With any other package
manager, and on Windows, install `protoc` yourself first, or the Cargo build fails.

### Installing from a mirror

moon's versions are listed from the Git tags of [moonrepo/moon](https://github.com/moonrepo/moon),
and downloaded from its GitHub releases. When your network can't reach GitHub, list versions from a
mirrored repository with [`versions-source`](<../(fundamentals)/config.mdx#tools-versions-source>),
and download from a mirror of the releases with
[`url-rewrites`](../advanced/http.mdx#url-rewrites).

```toml title="~/.prototools"
[tools.moon.versions-source]
git-url = "https://git.corp.internal/mirrors/moon.git"

[settings.url-rewrites]
'^https://github\.com/moonrepo/moon/releases/download/' = "https://mirror.corp.internal/moon/"
```

The mirrored repository must keep moon's `v`-prefixed tags, like `v3.0.0`, as other tags are
ignored. Release assets must keep their paths and file names, like
`v3.0.0/moon_cli-x86_64-unknown-linux-gnu.tar.xz`, along with their `.sha256` checksum files.

## Ecosystem

### Toolchains

moon uses proto itself to install the tools that its
[toolchains](<../../../moon/docs/(fundamentals)/toolchain.mdx>) need, like Node.js or Go. For each
toolchain you've enabled, it uses the version pinned in the
[`.prototools`](<../(fundamentals)/config.mdx>) at the root of the workspace, unless the toolchain
configures a [`version`](/moon/api/ToolchainPluginConfig#version) of its own. One file can then pin
moon, and every tool that your tasks run with:

```toml title=".prototools"
moon = "3.0.0"
node = "24.11.0"
pnpm = "10.20.0"
```

After cloning, [`proto install`](../commands/install.mdx) installs all of them, and moon runs each
task with the pinned versions. See
[installing with proto](<../../../moon/docs/(fundamentals)/toolchain.mdx#installing-with-proto>)
for how moon resolves each version.
