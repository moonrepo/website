---
title: proto status
---

List the tools that are active in the current directory, with the version that's configured, the
version it resolves to, whether that version is installed, and which file it was configured in. It's
the quickest way to answer "which version of `node` do I get here, and why?", and to see what's still
missing before running [`proto install`](./install.mdx). It only reports, and never installs, pins,
or updates a lockfile.

```shell
# List the tools for the current directory
$ proto status

# Include versions pinned in the global config
$ proto status --config-mode upwards-global

# Print as JSON, for scripts
$ proto status --json

# List the tools that still need to be installed
$ proto status --json | jq -r 'to_entries[] | select(.value.is_installed | not) | .key'
```

A tool is listed whenever proto [detects a version](<../(fundamentals)/detection.mdx>) for it,
whether from a [`.prototools`](<../(fundamentals)/config.mdx>) pin, an
[ecosystem file](<../(fundamentals)/detection.mdx#4-ecosystem-files>) like `.nvmrc`, or a
[`PROTO_<TOOL>_VERSION`](<../(fundamentals)/detection.mdx#2-environment-variable>) environment
variable, and that includes [built-in tools](<../(fundamentals)/(plugin)/tool.mdx#built-in-tools>)
you haven't pinned. Tools without a version are skipped, and the command fails when no tool has one.
When a tool has a [lockfile](../advanced/lockfile.mdx) record, its locked version is shown too.

Like [`proto install`](./install.mdx), it uses the
[`upwards`](<../(fundamentals)/config.mdx#upwards>) resolution mode by default, so versions that are
only pinned in the global [`~/.proto/.prototools`](<../(fundamentals)/config.mdx#locations>) aren't
listed. Pass `--config-mode upwards-global` to include them, which matches what shims see (see
[resolution modes](<../(fundamentals)/config.mdx#resolution-modes>)).

If any of the loaded configs haven't been [trusted](<../(fundamentals)/trust.mdx>), they're listed
above the table, with the
[security-sensitive settings](<../(fundamentals)/trust.mdx#security-sensitive-settings>) that were
ignored. This often explains a tool that seems to be missing, so review them, then run
[`proto trust`](./trust.mdx).

Pass the global [`--json`](./overview.mdx#output-formats) option for machine-readable output, keyed
by tool identifier. To dig into why a version was detected, see
[debugging detection](<../(fundamentals)/detection.mdx#debugging-detection>). To check whether newer
versions are available, use [`proto outdated`](./outdated.mdx).
