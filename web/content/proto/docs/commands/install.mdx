Download and install [tools](<../(fundamentals)/(plugin)/tool.mdx>) into the
[store](<../(fundamentals)/store.mdx>), where each version gets a directory of its own, so
installing one version never replaces another. The command is also available as `proto i`,
`proto u`, and `proto use`, and has two modes, depending on whether you name a tool:

- **One tool** - `proto install node 24` installs a single tool, at the version you pass, or the
  one [detected](<../(fundamentals)/detection.mdx#detection-order>) for the current directory, or
  `latest` when nothing is detected. Use it to try a version, set up a default for your machine, or
  move a tool forward to its newest release.
- **Every tool** - `proto install`, without arguments, installs every tool that has a version
  configured for the current directory, in a [`.prototools`](<../(fundamentals)/config.mdx>) or an
  ecosystem file, in parallel. Use it after cloning a repository (see
  [installing every tool](../start/team.mdx#installing-every-tool)), and whenever its pins change.

```shell
# Install every tool the current directory needs
$ proto install

# Install the newest Node.js 24 release, an exact version, or an alias
$ proto install node 24
$ proto install node 24.11.0
$ proto install node lts

# Install, then pin the resolved version as your default
$ proto install node 24 --pin global

# Build Python from source, instead of downloading a prebuilt
$ proto install python 3.13 --build

# Install Node.js, without installing its bundled npm
$ proto install node 24 -- --no-bundled-npm

# In CI, install exactly what the lockfile records, or fail
$ proto install --immutable-lockfile
```

Versions that are already installed are skipped, so the command is safe to run again and again
(pass `--force` to reinstall them). The two modes treat a partial version differently: installing
one tool resolves a partial version to the newest matching release, even when an older match
is installed, while installing every tool is satisfied by any matching version that's already
installed. To move a tool forward, install it by name, or update its pin
with [`proto outdated --update`](./outdated.mdx).

Neither mode installs the versions pinned in your global
[`~/.proto/.prototools`](<../(fundamentals)/config.mdx#locations>), only what the current directory
needs. When installing every tool, pass the global `--config-mode upwards-global` option to include
them. Some tools require another, and fail to install unless that tool has a version pinned too.
When a tool fails, its full log is written to `proto-<id>-install.log` in the current directory, and
the command exits with a non-zero code.

Installing a version doesn't [pin](<../(fundamentals)/config.mdx#pinning-versions>) it, so unless an
existing pin matches it, shims won't run it. Pass `--pin` to pin the resolved version, or enable
[`pin-latest`](<../(fundamentals)/config.mdx#pin-latest>) to pin it automatically when installing
`latest`. As `--pin` accepts an optional value, place it after the tool and version: in
`proto install node --pin 24`, `24` is read as the location, and the command fails.

When a [lockfile](../advanced/lockfile.mdx) applies to a tool, installs follow it: a locked version
is installed instead of the newest match (see [version
resolution](../advanced/lockfile.mdx#version-resolution)), the download must match the locked
checksum, and fresh installs are recorded in the `.protolock`. A version installed before you
enabled the lockfile isn't recorded until you reinstall it with `--force`. In CI, pass
`--immutable-lockfile`, so the lockfile decides what's installed instead of being changed by the
install (see [immutable lockfiles](../advanced/lockfile.mdx#immutable-lockfiles)).

You don't always have to run it yourself: with
[`auto-install`](<../(fundamentals)/config.mdx#auto-install>) enabled, running a tool through its
shim installs a missing version. To remove a version, run [`proto uninstall`](./uninstall.mdx).

## Arguments

- `[CONTEXT]` - The [identifier](<../(fundamentals)/(plugin)/tool.mdx#tool-identifiers>) of a single
  tool to install, or a [backend-prefixed](<../(fundamentals)/(plugin)/tool.mdx#backend-prefixed>)
  one. When omitted, every tool configured for the current directory is installed.
- `[SPEC]` - When installing one tool, the [version
  specification](<../(fundamentals)/version-spec.mdx>) to install. Defaults to the
  [detected](<../(fundamentals)/detection.mdx>) version, or `latest`.
- `-- [PASSTHROUGH...]` - When installing one tool, arguments to pass to the tool's plugin, for its
  install hooks. Which arguments are supported depends on the plugin.

## Options

- `--build` - [Build from source](../guides/build-from-source.mdx) instead of downloading a
  prebuilt, which may ask to install missing system packages first. When installing every tool,
  tools that can't be built from source are skipped.
- `--force` - Reinstall versions that are already installed. The download is still compared to the
  checksum recorded for the version, when one exists.
- `--immutable-lockfile` - Treat [lockfiles](../advanced/lockfile.mdx) as read-only, and fail when a
  version has no record for your platform. Can also be set with `PROTO_IMMUTABLE_LOCKFILE`.
- `--no-build` - Download a prebuilt instead of building from source, for tools that build from
  source by default. When installing every tool, tools without a prebuilt are skipped.
- `--pin` <TypeLabel type="closest | global | local | user" /> - After installing, pin the resolved
  version to the [`.prototools`](<../(fundamentals)/config.mdx>) at this
  [location](<../(fundamentals)/config.mdx#writing-to-a-file>). Defaults to `closest`.
- `--quiet` - Hide the install's progress output, except for errors.
- `--update-lockfile` - Ignore each specification's [lockfile](../advanced/lockfile.mdx) record,
  resolve it again, and replace the record with the result.
