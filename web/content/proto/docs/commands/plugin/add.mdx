Register a [plugin](<../../(fundamentals)/(plugin)/plugin.mdx>) for a tool or backend in a
[`.prototools`](<../../(fundamentals)/config.mdx>) file, under an ID of your choosing, instead of
[enabling the plugin](<../../(fundamentals)/(plugin)/plugin.mdx#enabling-plugins>) by hand. Reach
for it to bring in a [third-party tool](<../../(fundamentals)/(plugin)/tool.mdx#third-party-tools>)
or [backend](<../../(fundamentals)/(plugin)/backend.mdx#third-party-backends>), or to
[override a built-in tool](<../../(fundamentals)/(plugin)/tool.mdx#overriding-built-in-tools>).
Built-in and [community tools](<../../(fundamentals)/(plugin)/tool.mdx#community-tools>) work by ID,
so they don't need to be added. To find a third-party plugin and its locator, use
[`proto plugin search`](./search.mdx).

```shell
# Add a tool plugin from a GitHub release, to the closest .prototools
$ proto plugin add my-tool "github://my-org/my-tool-plugin@v1.0.0"

# Override the built-in Node.js plugin with a local build
$ proto plugin add node "file://./target/wasm32-wasip1/release/node_tool.wasm"

# Add a schema plugin from a URL, to the .prototools in the current directory
$ proto plugin add example "https://example.com/plugins/example.toml" --to local

# Add a backend plugin from an OCI registry, to your user config
$ proto plugin add my-backend "registry://ghcr.io/my-org/my_backend:0.1.0" --type backend --to user
```

By default, the plugin is added to the [closest](<../../(fundamentals)/config.mdx#closest>)
[`.prototools`](<../../(fundamentals)/config.mdx>), or a new one in the current directory when there
is none. The locator is written to the file's
[`[plugins]`](<../../(fundamentals)/config.mdx#plugins>) table if it has one, otherwise to the
[`plugin`](<../../(fundamentals)/config.mdx#tools-plugin>) setting of a `[tools.<id>]` table (or
with `--type backend`, the [`plugin`](<../../(fundamentals)/config.mdx#backends-plugin>) setting of
a `[backends.<id>]` table). Running the command again for the same ID overwrites the locator. To use
a plugin in every project, add it with `--to user` rather than `--to global`, as the global config
isn't loaded by commands that act on a project.

Once the file is written, proto loads the plugin to verify that it works, which fails if the plugin
can't be found, isn't a valid plugin, or requires a newer version of proto. An entry that fails to
load stays in the file, so fix the locator and run the command again, or remove the entry with
[`proto plugin remove`](./remove.mdx).

<Callout type="warning">
  A relative `file://` path is resolved from the directory of the
  [`.prototools`](<../../(fundamentals)/config.mdx>) it's written to, but
  verified from the current directory. Run the command from that file's
  directory, or use an absolute path, so both agree.
</Callout>

If the file had no [security-sensitive
settings](<../../(fundamentals)/trust.mdx#security-sensitive-settings>) before, proto [trusts it
automatically](<../../(fundamentals)/trust.mdx#automatically-trusted>). A project config that
already had untrusted settings stays untrusted, and other commands ignore the plugin until you run
[`proto trust`](../trust.mdx).

## Arguments

- `<ID>` - The ID to register the plugin under, which is how you reference the tool in pins and
  commands. A backend's ID is the prefix of its tools. Using the ID of a built-in tool or backend
  overrides its built-in plugin.
- `<PLUGIN>` - The [plugin locator](../../../../wasm/docs/plugin-locators.mdx) to load the plugin
  from: a `file://` path, an `https://` URL, a `github://` release, or a `registry://` image. A
  `github://` locator uses the latest release unless you append `@<tag>`.

## Options

- `--to` <TypeLabel type="closest | global | local | user" /> - The
  [location](<../../(fundamentals)/config.mdx#writing-to-a-file>) of the
  [`.prototools`](<../../(fundamentals)/config.mdx>) to add the plugin to. Defaults to `closest`.
  Also accepts `cwd`, `home`, and `store`, as aliases of `local`, `user`, and `global`.
- `--type` <TypeLabel type="backend | tool" /> - The [type of
  plugin](<../../(fundamentals)/(plugin)/plugin.mdx#plugin-types>) to add. Defaults to `tool`.
  Backends must be [WASM](<../../(fundamentals)/(plugin)/plugin.mdx#wasm>) plugins.
