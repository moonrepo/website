Removes what proto has put in the [store](<../(fundamentals)/store.mdx>) but no longer uses: tool
versions you haven't run in a while, downloaded plugins, temporary files, cached HTTP responses, and
[trust](<../(fundamentals)/trust.mdx>) records for paths that were deleted. The store only grows on
its own, as every install, plugin update, and cached request adds to it, so run this command every
so often to reclaim disk space, or in CI before a cached store is saved (see
[caching the store](../guides/ci.mdx#caching-the-store)).

What counts as unused is measured in days, with `--days` (30 by default):

- **Tool versions** use the [last used](<../(fundamentals)/store.mdx#last-used>) timestamp that
  proto records each time it runs a version. A version that has never run through proto has no
  timestamp, so it's never removed by age, and neither is a version installed with `PROTO_NO_CLEAN`
  set. Version directories that the tool's [manifest](<../(fundamentals)/store.mdx#manifest>)
  doesn't track, like the leftovers of an interrupted install, are removed regardless of age.
- **proto's own versions**, in `~/.proto/tools/proto`, use when their `proto` executable was last
  accessed.
- **Plugins, temporary files, and cache files** use when the file was last accessed on disk, so a
  plugin that proto loads regularly is kept. Hidden files are always kept.

Only tools that proto can load where you run the command are checked: every
[built-in tool](<../(fundamentals)/(plugin)/tool.mdx#built-in-tools>), and every tool with a plugin
or version configured in the [`.prototools`](<../(fundamentals)/config.mdx>) files that apply,
which are those found upwards from the current directory, plus the global one (the
[`upwards-global`](<../(fundamentals)/config.mdx#upwards-global>) mode). So a third-party or
[backend](<../(fundamentals)/(plugin)/backend.mdx>) tool that's only configured in a repository is
only cleaned when you run the command inside that repository. Tools that keep their inventory
[outside the store](<../(fundamentals)/store.mdx#custom-locations>), like Rust, are skipped. See
[stale versions](<../(fundamentals)/store.mdx#stale-versions>) for the full rules.

Before removing a tool's stale versions, proto lists them and asks for confirmation, once per tool.
Declining keeps that tool's versions and moves on to the next tool. The prompt is skipped, and the
versions are removed, when the global `--yes` option is passed (see [prompts](./overview.mdx#prompts))
or in a CI environment. When the output isn't a terminal, like in a script or a pipe, the prompt
can't be shown and the versions are kept, so always pass `--yes` in scripts. Everything else,
including proto's own versions, is removed without asking.

A stale version is uninstalled like [`proto uninstall`](./uninstall.mdx) would: its directory and
manifest entry are removed, its executables in `bin` are removed or re-pointed to the highest
remaining version, and removing a tool's last version also removes its shims. Unlike uninstalling,
cleaning never touches your configuration. Pins in [`.prototools`](<../(fundamentals)/config.mdx>)
files, and records in [lockfiles](../advanced/lockfile.mdx), are kept, as the version may still be
required by a repository, or used on other machines. Run [`proto install`](./install.mdx) to install
it again when it's needed.

When it's done, proto prints how many items were removed of each type, along with the disk space
freed by plugins, temporary files, and cache files. With the global `--json` option (see
[output formats](./overview.mdx#output-formats)), it prints what was removed instead: an object with
`cache`, `plugins`, and `temp` lists of `{ file, size }` (size in bytes), a `tools` list of
`{ dir, id, version }`, and a `trust` list of paths.

```shell
# Clean everything that hasn't been used in 30 days
$ proto clean

# Clean only installed tool versions, without prompting
$ proto clean tools --yes

# Clean everything that hasn't been used in a week
$ proto clean --days 7

# Remove every cached HTTP response, regardless of age
$ proto clean cache --days 0

# Remove trust records for deleted repositories
$ proto clean trust

# Clean everything in a script, and print what was removed as JSON
$ proto clean --yes --json
```

To clean without having to remember, enable the [`auto-clean`](<../(fundamentals)/config.mdx#auto-clean>)
setting. proto then cleans every target, with the default of 30 days and without prompting, after
[`proto activate`](./activate.mdx), [`proto install`](./install.mdx),
[`proto outdated`](./outdated.mdx), [`proto regen`](./regen.mdx), and
[`proto status`](./status.mdx). See [automatic cleaning](<../(fundamentals)/store.mdx#automatic-cleaning>).

## Arguments

- `[TARGET]` - The type of artifact to clean. Defaults to `all`.
  - `all` - Every target below.
  - `cache` - Files in `~/.proto/cache`, like cached HTTP responses and plugin registries, that
    haven't been accessed within `--days`. Directories left empty are removed too.
  - `plugins` - Downloaded plugin files in `~/.proto/plugins` that haven't been accessed within
    `--days`. They're downloaded again the next time they're needed.
  - `temp` - Files directly in `~/.proto/temp` that haven't been accessed within `--days`.
    Directories are left alone, as in-progress installs and plugin downloads manage them.
  - `tools` - Stale and untracked versions of installed tools, and proto's own versions, as
    described above.
  - `trust` - [Trust](<../(fundamentals)/trust.mdx>) records for config files and directories that
    no longer exist, or that can't be read, regardless of age. Otherwise, a record for a deleted path
    would trust a different repository that's later cloned to the same path. To remove a record for
    a path that still exists, use [`proto untrust`](./untrust.mdx).

## Options

- `--days` <TypeLabel type="number" /> - The number of days since an item was last used (or
  accessed) before it's considered stale, as a whole number from `0` to `255`. With `0`, everything
  is stale, apart from the exceptions above. Doesn't apply to the `trust` target, or to untracked
  version directories. Defaults to `30`.
