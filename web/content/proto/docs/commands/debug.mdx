---
title: proto debug
---

When proto doesn't behave the way you expect, like a pinned version that's ignored, a setting that
doesn't apply, or a tool that's installed somewhere unexpected, the `proto debug` sub-commands show
you what proto actually sees. They print the state that every other command works from: the
[`.prototools`](<../(fundamentals)/config.mdx>) files proto found and the configuration they
merge into, and the [store](<../(fundamentals)/store.mdx>) and environment that proto runs in.

This command does nothing on its own, and exists purely to group the following sub-commands:

- [`proto debug config`](./debug/config.mdx) - Print every
  [`.prototools`](<../(fundamentals)/config.mdx>) that proto found, from lowest to highest
  precedence, followed by the final merged configuration.
- [`proto debug env`](./debug/env.mdx) - Print the store paths, the proto version, operating system
  and architecture, the config files that proto found, and every `PROTO_*`
  [environment variable](../advanced/env-vars.mdx) that's set.

```shell
# Print each .prototools, and the configuration they merge into
$ proto debug config

# Print the store paths, config sources, and PROTO_* variables
$ proto debug env

# Print the environment as JSON, to attach to a bug report
$ proto debug env --json
```

Both sub-commands merge configuration in
[`upwards-global`](<../(fundamentals)/config.mdx#upwards-global>) mode by default, like most
commands, so the merged result matches what [`proto run`](./run.mdx) and shims see from the current
directory. Pass the global `--config-mode` option to merge in another
[resolution mode](<../(fundamentals)/config.mdx#resolution-modes>) instead. The list of files is
the same in every mode: it shows every file proto found, not only the ones the mode merges. Both also support
the global `--json` option for [machine-readable output](./overview.mdx#output-formats), and a
`--raw` flag that dumps proto's internal data structures, which is mostly useful when reporting a
bug.

For a health check of your installation as a whole, like `PATH` ordering and shell setup, run
[`proto diagnose`](./diagnose.mdx) instead. See the
[troubleshooting guide](../guides/troubleshooting.mdx#inspecting-configuration) for more ways to
track down a problem.
