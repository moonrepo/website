Pins a version of a tool by writing it to a [`.prototools`](<../(fundamentals)/config.mdx>) file,
where it becomes the version that proto [detects](<../(fundamentals)/detection.mdx>) for the tool,
in that file's directory and every directory beneath it. It's how a project declares the versions
it needs, and how you choose fallback versions for your machine. The command is also available as
`proto p`. New to pinning? Start with [pin versions](../start/versions.mdx).

```shell
# Pin a version to the closest .prototools
$ proto pin node 24

# Pin the exact version that an alias currently resolves to, like 24.11.0
$ proto pin node stable --resolve

# Pin a fallback version, used in any directory that doesn't pin its own
$ proto pin go 1.25 --to global

# Override a version for the current directory only
$ proto pin node 22 --to local

# Pin to devEngines in package.json, instead of .prototools
$ proto pin pnpm latest --resolve --tool-native
```

The spec replaces the tool's previous pin, if any, and the rest of the file, including its comments,
is left as-is. Partial versions are written with their operator, so `24` is written as `~24`, which
[means the same thing](<../(fundamentals)/version-spec.mdx#requirements-and-ranges>). Pinning
doesn't install anything, and without `--resolve` the spec isn't checked against the tool's
available versions, so run [`proto install`](./install.mdx) afterwards (or enable
[`auto-install`](<../(fundamentals)/config.mdx#auto-install>)). To install and pin in one step, run
[`proto install --pin`](./install.mdx), and to remove a pin, run [`proto unpin`](./unpin.mdx).

By default, the [closest](<../(fundamentals)/config.mdx#closest>)
[`.prototools`](<../(fundamentals)/config.mdx>) is written, or `./.prototools` is created if there
are none, so pinning from anywhere within a repository updates the file at its root. When that file
enables a [lockfile](../advanced/lockfile.mdx), its `.protolock` is kept in sync.

Pins for tools without a built-in plugin, like community tools, are
[security-sensitive](<../(fundamentals)/trust.mdx#security-sensitive-settings>), and pinning one
[trusts the file](<../(fundamentals)/trust.mdx#automatically-trusted>), unless it already had
untrusted settings. The reserved `proto` identifier
[pins proto itself](<../(fundamentals)/config.mdx#pinning-proto>), but only from a project file, as
the pin is ignored in your user and global files.

## Arguments

- `<CONTEXT>` - The tool to pin, by its
  [identifier](<../(fundamentals)/(plugin)/tool.mdx#tool-identifiers>), like `node`, or a
  [backend](<../(fundamentals)/(plugin)/backend.mdx>) prefixed identifier, like `npm:prettier`.
- `<SPEC>` - The [version specification](<../(fundamentals)/version-spec.mdx>) to pin: a version,
  partial version, requirement, range, or alias. Quote specs that contain spaces or shell operators,
  like `">=20 <23"`.

## Options

- `--resolve` - Resolve the spec to a fully-qualified version, like `stable` to `24.11.0`, and pin
  that version instead, so every machine runs the same version. Fails if no version matches.
- `--to` <TypeLabel type="closest | global | local | user" /> - The
  [location](<../(fundamentals)/config.mdx#writing-to-a-file>) of the
  [`.prototools`](<../(fundamentals)/config.mdx>) to write: the closest file (`closest`, the
  default), `./.prototools` (`local`), `~/.prototools` (`user`), or `~/.proto/.prototools`
  (`global`).
- `--tool-native` - Pin the version in the tool's own
  [ecosystem file](<../(fundamentals)/detection.mdx#4-ecosystem-files>) instead, like `devEngines`
  in `package.json` for Node.js and its package managers, so tooling outside of proto sees the same
  version. The `package.json` must already exist in the directory picked by `--to`, and
  `devEngines` doesn't support aliases, so pass `--resolve` to pin one.
