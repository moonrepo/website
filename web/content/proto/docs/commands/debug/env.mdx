---
title: proto debug env
---

Print a snapshot of the environment that proto runs in: where its
[store](<../../(fundamentals)/store.mdx>) is, which version of proto is running and on which
platform, which [`.prototools`](<../../(fundamentals)/config.mdx>) files it found, and which `PROTO_*`
environment variables are set.

Reach for it when proto behaves differently in one place than in another. Every proto process works
out its store and configuration from its own environment and working directory, so an editor, a CI
job, or a script can end up with a different `PROTO_HOME`, miss a
[`.prototools`](<../../(fundamentals)/config.mdx>), or inherit a stray variable like
`PROTO_NODE_VERSION`. Run this command in the same context, and from the directory you're
troubleshooting, to see what proto sees there. It's also a quick way to collect the version and
platform details for a bug report. See
[inspecting the environment](../../guides/troubleshooting.mdx#inspecting-the-environment) for more
troubleshooting tips.

```shell
# Print the environment for the current directory
$ proto debug env

# Print the same information as JSON, for scripts
$ proto debug env --json

# Print the store's root directory
$ proto debug env --json | jq -r '.store.dir'

# Dump proto's internal environment structures
$ proto debug env --raw
```

The output has a store section and an environment section:

```text
Store ──────────────────────────

  Root: /Users/name/.proto
  Bins: /Users/name/.proto/bin
  Shims: /Users/name/.proto/shims
  Plugins: /Users/name/.proto/plugins
  Tools: /Users/name/.proto/tools
  Temp: /Users/name/.proto/temp

Environment ────────────────────

  Proto version: 0.63.2
  Operating system: macos
  Architecture: arm64
  Config sources:
    - /Users/name/Projects/app/.prototools
    - /Users/name/.prototools
    - /Users/name/.proto/.prototools
  Virtual paths:
    /temp = /Users/name/.proto/temp
    /proto = /Users/name/.proto
    /userhome = /Users/name
  Environment variables:
    PROTO_APP_LOG = info
    PROTO_HOME = /Users/name/.proto
    PROTO_OFFLINE_TIMEOUT = 750
    PROTO_VERSION = 0.63.2
```

- **Store** - The root of the store, and the `bin`, `shims`, `plugins`, `tools` (the inventories),
  and `temp` directories within it. The root follows `PROTO_HOME` (or `XDG_DATA_HOME`), while
  `PROTO_TEMP_DIR` and `PROTO_PLUGINS_DIR` move the temp and plugins directories on their own, so
  this is where to confirm that they took effect. See
  [store location](<../../(fundamentals)/store.mdx#store-location>) and
  [directory layout](<../../(fundamentals)/store.mdx#directory-layout>).
- **Proto version** - The version of proto that's running. Use it to confirm that a
  [pinned proto version](<../../(fundamentals)/config.mdx#pinning-proto>) is in effect, as the pin
  only applies through [shell activation](<../../(fundamentals)/workflows.mdx#shell-activation>).
- **Operating system** and **Architecture** - The host platform, as proto detected it.
- **Config sources** - Every [`.prototools`](<../../(fundamentals)/config.mdx>) that exists, from
  highest to lowest precedence: the current directory and each of its parents, then the user
  `~/.prototools` and the global `~/.proto/.prototools` (see
  [locations](<../../(fundamentals)/config.mdx#locations>)). With
  [environment mode](<../../(fundamentals)/config.mdx#environment-mode>), each `.prototools.<env>` is
  listed before the [`.prototools`](<../../(fundamentals)/config.mdx>) in the same directory. The
  list doesn't depend on the
  [resolution mode](<../../(fundamentals)/config.mdx#resolution-modes>), so it includes the global
  file, even though commands like [`proto install`](../install.mdx) don't load it. Files that
  haven't been [trusted](<../../(fundamentals)/trust.mdx>) are listed too, though their
  security-sensitive settings are ignored, and proto logs a warning about them. To see what each
  file contains, and the configuration they merge into, run [`proto debug config`](./config.mdx).
- **Virtual paths** - The directories on your machine that are mapped into the sandbox that
  [WASM plugins](<../../(fundamentals)/(plugin)/plugin.mdx#wasm>) run in, as `virtual = real`.
  Plugins can access the store's temp directory (`/temp`), the store (`/proto`), and your home
  directory (`/userhome`). When proto runs outside of your home directory, the current directory is
  mapped to `/cwd` as well. A plugin can't access files outside of these directories. See
  [virtual paths](../../../../wasm/docs/virtual-paths.mdx).
- **Environment variables** - Every variable whose name starts with `PROTO_`, sorted by name, so
  related variables like `XDG_DATA_HOME`, `CI`, or `HTTPS_PROXY` aren't shown. A few are set by proto
  itself, so they appear even when you haven't set them: `PROTO_APP_LOG` (the log level),
  `PROTO_VERSION`, and `PROTO_OFFLINE_TIMEOUT`, along with `PROTO_OFFLINE_HOSTS` and
  `PROTO_OFFLINE_OVERRIDE_HOSTS` when
  [`[settings.offline]`](<../../(fundamentals)/config.mdx#settingsoffline>) configures them. The
  rest come from your environment: those you set, like `PROTO_HOME` in your shell profile, and
  those that proto [sets for the tools it runs](../../advanced/env-vars.mdx#within-tool-processes),
  like `PROTO_<TOOL>_VERSION`, when proto runs from within a tool's process, like an npm script. A
  leftover
  [version override](../../advanced/env-vars.mdx#version-overrides) takes precedence over every
  [`.prototools`](<../../(fundamentals)/config.mdx>), so this is the first place to look when proto
  runs an unexpected version. See [environment variables](../../advanced/env-vars.mdx) for what each
  one does.

<Callout type="warning">
  Values are printed as-is, including secrets like `PROTO_GITHUB_TOKEN`. Remove them before sharing
  the output, like in a bug report.
</Callout>

With `--json`, or `--reporter json` (see [global options](../overview.mdx#global-options)), the same
information is printed as a JSON object with 2 keys. `store` holds every directory of the store,
including those the text output leaves out: `dir`, `backends_dir`, `bin_dir`, `builders_dir`,
`cache_dir`, `inventory_dir`, `plugins_dir`, `plugins_temp_dir`, `shims_dir`, and `temp_dir`. `env`
holds `arch`, `os`, `proto_version`, `configs`, `vars`, and `virtual_paths` (a map of real paths to
virtual paths). With `--reporter ndjson`, the default when an AI agent runs proto, the object is
printed on a single line, wrapped as `{"type":"data","data":{...}}`. See
[JSON output](../../guides/reporting.mdx#json-output).

## Options

- `--raw` - Print proto's internal environment structures to stderr, with Rust's debug formatting,
  instead of the output above. They include details that the other formats don't, like the
  [resolution mode](<../../(fundamentals)/config.mdx#resolution-modes>), the
  [environment mode](<../../(fundamentals)/config.mdx#environment-mode>) (`PROTO_ENV`), the home and
  working directories, and how configs are [trusted](<../../(fundamentals)/trust.mdx>): the
  directory of trust records, whether every config is trusted (as in CI), and the directories of
  `PROTO_TRUSTED_PATHS`. It takes precedence over `--json`, and its format isn't stable, so use it
  for debugging rather than in scripts.
