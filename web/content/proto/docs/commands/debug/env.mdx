---
title: proto debug env
---

Print a snapshot of the environment that proto runs in: where its
[store](<../../(fundamentals)/store.mdx>) is, which version of proto is running and on which
platform, which [`.prototools`](<../../(fundamentals)/config.mdx>) files it found, and which
`PROTO_*` environment variables are set.

Reach for it when proto behaves differently in one place than in another. An editor, a CI job, or a
script can end up with a different `PROTO_HOME`, miss a
[`.prototools`](<../../(fundamentals)/config.mdx>), or inherit a stray `PROTO_*` variable. Run this
command in the same context, and from the directory you're troubleshooting, to see what proto sees
there. It's also a quick way to collect the version and platform details for a bug report.

```shell
# Print the environment for the current directory
$ proto debug env

# Print the same information as JSON, for scripts
$ proto debug env --json

# Print the store's root directory
$ proto debug env --json | jq -r '.store.dir'
```

The output includes:

- **Store** - The store's root, and the directories within it. Check here that `PROTO_HOME`,
  `PROTO_TEMP_DIR`, or `PROTO_PLUGINS_DIR` took effect. See [store
  location](<../../(fundamentals)/store.mdx#store-location>).
- **Proto version** - The version of proto that's running. Use it to confirm that a
  [pinned proto version](<../../(fundamentals)/config.mdx#pinning-proto>) is in effect, as the pin
  only applies through [shell activation](<../../(fundamentals)/workflows.mdx#shell-activation>).
- **Config sources** - Every [`.prototools`](<../../(fundamentals)/config.mdx>) that exists, from
  highest to lowest precedence. The list doesn't depend on the
  [resolution mode](<../../(fundamentals)/config.mdx#resolution-modes>), and includes files that
  haven't been [trusted](<../../(fundamentals)/trust.mdx>). To see what each file contains, and the
  configuration they merge into, run [`proto debug config`](./config.mdx).
- **Virtual paths** - The directories on your machine that [WASM
  plugins](<../../(fundamentals)/(plugin)/plugin.mdx#wasm>) can access. See [virtual
  paths](../../../../wasm/docs/virtual-paths.mdx).
- **Environment variables** - Every variable whose name starts with `PROTO_`, including a few that
  proto sets itself. Other variables aren't shown.

<Callout type="warning">
  Values are printed as-is, including tokens and other secrets. Remove them
  before sharing the output.
</Callout>

See [inspecting the environment](../../guides/troubleshooting.mdx#inspecting-the-environment) for
more troubleshooting tips.

## Options

- `--raw` - Print proto's internal environment structures to stderr, with Rust's debug formatting,
  instead of the output above. It takes precedence over `--json`, and its format isn't stable, so
  use it for debugging rather than in scripts.
