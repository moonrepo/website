Configure your environment so that proto, and the tools it installs, can be found. It puts the
`shims` and `bin` directories of the [store](<../(fundamentals)/store.mdx>) on your `PATH`, which
is all that [shims](<../(fundamentals)/workflows.mdx#shims>) and
[binary linking](<../(fundamentals)/workflows.mdx#binary-linking>) need to work, by appending a few
lines to your shell profile. [Shell activation](<../(fundamentals)/workflows.mdx#shell-activation>)
is separate and opt-in (see [`proto activate`](./activate.mdx)).

You rarely need to run it by hand. The [Bash install script](../index.mdx#macos-linux-and-wsl) runs
it as its last step, and passes any options you give the script through to it. After installing
with the [PowerShell install script](../index.mdx#windows), or any other way, run it yourself.

```shell
# Set up the detected shell, choosing the profile to update from a prompt
$ proto setup

# Set up Fish, using the defaults instead of prompting
$ proto setup --shell fish --yes

# Print the lines to add to a profile, without changing anything
$ proto setup --no-modify-profile --no-modify-path
```

proto detects your shell from `$SHELL` and its parent processes, and asks you to pick one when it
can't. `$SHELL` holds your _login_ shell, so pass `--shell` when you're running a different one. It
then lists the profile files for that shell, and asks which one to update. You can also enter a path
of your own, or choose none. Set the [`PROTO_SHELL_PROFILE`](../advanced/env-vars.mdx#installation)
environment variable to use a single file instead. For Bash and Zsh, the appended lines look like
this:

```shell title="~/.zshrc"
# proto
export PROTO_HOME="$HOME/.proto";
export PATH="$PROTO_HOME/shims:$PROTO_HOME/bin:$PATH";
```

On Windows, proto also prepends the `shims` and `bin` directories to the `Path` of your user
account, which doesn't require administrator access, and covers programs that don't load your
profile.

A few more things to know:

- **Open a new terminal.** Your current terminal isn't affected by the changes.
- **It only sets up a shell without proto.** When the `shims` or `bin` directory is already on the
  current `PATH`, proto exits without changing anything. A shell you start from one that's set up
  inherits its `PATH`, so to add proto to another shell, add the lines
  to that shell's profile yourself.
- **It never duplicates lines.** proto only appends to a profile that doesn't mention `PROTO_HOME`.
  A profile that already sets it is left as is, so add the `PATH` line to it yourself.
- **Pass `--yes` in scripts.** The global `--yes` option (see [prompts](./overview.mdx#prompts))
  skips the prompts, and picks the first profile that exists, or creates one. Without it, when the
  output isn't a terminal, the first option of each prompt is selected, which may be a profile that
  doesn't exist yet. Prompts are also skipped in CI.

proto remembers the profile it chose, and adds to it when a tool needs environment variables after
it's installed. [`proto diagnose`](./diagnose.mdx) reports it. To undo the setup, follow
[uninstalling](../index.mdx#uninstalling).

## Options

- `--shell` <TypeLabel type="ash | bash | dash | elvish | fish | ion | murex | nu | powershell | pwsh | sh | xonsh | zsh" /> - The shell to set up, which determines the syntax of the lines and
  the profiles to choose from. Defaults to detecting the current shell.
- `--no-modify-profile` - Don't append the lines to a shell profile. Also available as
  `--no-profile`, or by setting the `PROTO_NO_MODIFY_PROFILE` environment variable to `true`.
- `--no-modify-path` - Don't add proto's directories to the `Path` of your user account. Only has an
  effect on Windows. Can also be set with the `PROTO_NO_MODIFY_PATH` environment variable, set to
  `true`.
