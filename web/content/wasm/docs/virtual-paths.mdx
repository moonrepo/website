WASM doesn't have access to the host file system by default, but through [WASI](https://wasi.dev/),
we can provide sandboxed access to a pre-defined list of allowed directories. We call these
[virtual paths](https://docs.rs/warpgate_api/latest/warpgate_api/struct.VirtualPath.html), and all
paths provided via function input or context use them.

## Prefixes

Virtual paths are implemented by mapping a real path (host machine) to a virtual path (guest
runtime) using file path prefixes. The following prefixes are supported in moon:

| Real path                             | Virtual path |
| ------------------------------------- | ------------ |
| `~` (user home directory)             | `/userhome`  |
| `~/.moon` (or `MOON_HOME`)            | `/moon`      |
| `~/.proto` (or `PROTO_HOME`)          | `/proto`     |
| `~/.proto/temp` (or `PROTO_TEMP_DIR`) | `/temp`      |
| moon workspace root                   | `/workspace` |

And the following prefixes are supported in proto:

| Real path                             | Virtual path |
| ------------------------------------- | ------------ |
| `~` (user home directory)             | `/userhome`  |
| `~/.proto` (or `PROTO_HOME`)          | `/proto`     |
| `~/.proto/temp` (or `PROTO_TEMP_DIR`) | `/temp`      |
| Current working directory             | `/cwd`       |

The `/cwd` prefix is only mapped when proto runs outside of the home directory, as the working
directory is otherwise already accessible through `/userhome`.

For example, from the context of WASM, you may have a virtual path of `/proto/tools/node/1.2.3`,
which maps back to `~/.proto/tools/node/1.2.3` on the host machine. This should almost always be
transparent to you, the developer, and to end users. When a path matches multiple prefixes, the
most specific one wins, so `~/.proto/temp/file` maps to `/temp/file`, not `/proto/temp/file`.

## Path types

The `VirtualPath` type is a newtype wrapper around Rust's `PathBuf`, with a sibling
[`RealPath`](https://docs.rs/warpgate_api/latest/warpgate_api/struct.RealPath.html) type that
represents a real path on the host machine. Both types dereference to `PathBuf`, so all `Path` and
`PathBuf` methods are available, and the `join`, `parent`, `with_extension`, `with_file_name`, and
`with_added_extension` methods return the same type.

```rust
let dir = VirtualPath::new("/proto/tools/node");
let file = dir.join("1.2.3/bin/node"); // `VirtualPath`
```

`VirtualPath::new` and `RealPath::new` wrap the provided value as-is, and don't validate or convert
it. To create a path from the other kind, [convert it](#converting-paths) instead.

However, there are a few cases where you need the real path from WASM, for example, when logging
or executing commands. For this, use the `to_real_path` method, which returns `None` if the path
can't be mapped. Jump to [converting paths](#converting-paths) for more information.

```rust
let real_path = virtual_path.to_real_path()?; // `Option<RealPath>`
```

## Paths in host functions

Most [host functions](./host-funcs.mdx) accept virtual paths, and convert them to real paths on
the host for you:

- The `command`, `cwd`, and `paths` fields when [executing commands](./host-funcs.mdx#executing-commands).
- The destination `file` when [downloading files](./host-funcs.mdx#downloading-files).
- The values appended to `PATH` when [setting environment variables](./host-funcs.mdx#environment-variables).

Other values are passed to the host as-is, most notably command arguments and environment variable
values (other than `PATH`). When passing a path to a command through these, convert it to a real
path first.

```rust
let archive = VirtualPath::new("/temp/node.tar.gz");

if let Some(file) = archive.to_real_path()? {
    exec_captured("tar", ["-xzf", &file.to_string()])?;
}
```

## File system caveats

When working with the file system from the context of WASM, there are a few caveats to be aware of.

- All `fs` calls must use virtual paths. Real paths will error.
- Paths outside of the allowed directories (the prefixes above) will error.
- Virtual paths always use forward slashes, even on Windows. Use forward slashes when joining paths
  in WASM, as mixing separators causes issues. Real paths are converted to the host's native
  separators.
- Changing file permissions is not supported (on Unix and Windows), as WASI doesn't support it.
  This also means operations like unpacking archives aren't possible in WASM. Instead,
  [execute a command](./host-funcs.mdx#executing-commands) on the host, like `tar` or `unzip`.

## Converting paths

When working with virtual paths, you may need to convert them to real paths, and vice versa. The
[`VirtualPathExt`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/trait.VirtualPathExt.html) and
[`RealPathExt`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/trait.RealPathExt.html) extension
traits provide `create` constructors and conversion methods for such situations. These aren't
[host functions](./host-funcs.mdx). Conversions happen directly in the guest, using the list of
host-to-guest path mappings provided by the host.

```rust
// Create a virtual path from a real path (errors if it can't be mapped)
let virt = VirtualPath::create("/some/real/path")?;

// Convert a virtual path into a real path (returns an `Option`)
let real = virt.to_real_path()?;

// And the inverse
let real = RealPath::create("/userhome/some/virtual/path")?;
let virt = real.to_virtual_path()?;
```

For lower-level control, the
[`convert_to_virtual_path`](https://docs.rs/warpgate_api/latest/warpgate_api/fn.convert_to_virtual_path.html)
and [`convert_to_real_path`](https://docs.rs/warpgate_api/latest/warpgate_api/fn.convert_to_real_path.html)
functions can be used instead, paired with
[`get_host_to_guest_paths`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/fn.get_host_to_guest_paths.html).
Both return `None` when the path doesn't match any prefix.

```rust
let real = convert_to_real_path("/workspace/app", get_host_to_guest_paths()?);
```
