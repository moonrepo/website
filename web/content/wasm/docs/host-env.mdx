---
title: Host environment
icon: Monitor
---

Since WASM executes in its own runtime, it _does not_ have access to the host's operating system,
architecture, and so on. To bridge this gap, we provide the
[`get_host_environment`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/fn.get_host_environment.html)
function, which returns a
[`HostEnvironment`](https://docs.rs/warpgate_api/latest/warpgate_api/struct.HostEnvironment.html).

```rust
let env = get_host_environment()?;
```

The host operating system and architecture can be accessed with the `os` and `arch` fields
respectively. Both fields are an enum in Rust, or a string in other languages.

```rust
if env.os == HostOS::Windows {
    // Windows only
}

if env.arch == HostArch::Arm64 {
    // aarch64 only
}
```

On Linux, the libc implementation can be accessed with the `libc` field, which is either
`HostLibc::Gnu` or `HostLibc::Musl`, and `HostLibc::Unknown` on other operating systems. Values that
aren't supported by your plugin's version of the PDK (for example, a libc added in the future) are
deserialized as `HostLibc::Unknown` instead of failing, so be sure to handle that case.

```rust
if env.libc == HostLibc::Musl {
    // Alpine, etc
}
```

Furthermore, the `ci` field is true when running in a CI environment, and the user's home
directory (`~`) can be accessed with the `home_dir` field, which is a
[virtual path](./virtual-paths.mdx).

```rust
if env.home_dir.join(".config/example").exists() {
    // Do something
}
```
