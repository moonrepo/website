title: Host functions

WASM is powerful, but it can't do everything since it's sandboxed. To work around this, we provide
host functions, which are functions implemented on the host (in Rust) that can be called from WASM.
The following host functions are available to all plugins:

- `download_file` - Download a file from a URL directly to a file on the host machine, without
  loading the contents into WASM memory.
- `exec_command` - Execute a command on the host machine, with a provided list of arguments,
  environment variables, and more.
- `get_env_var` - Get an environment variable value from the host environment.
- `host_log` - Log a message to the host's terminal (stdout or stderr), or to its logs.
- `send_request` - Request a URL on the host machine using a Rust-based HTTP client (not WASM).
- `set_env_var` - Set an environment variable on the host environment.

Our PDKs wraps these host functions in friendlier functions and macros, which are
covered in the sections below. The functions can be used as-is, but the macros call the host
function directly, so you'll need to declare the host functions you use at the top of your Rust
file with the `host_fn` attribute from the [extism-pdk](https://crates.io/crates/extism-pdk) crate.

```rust
#[host_fn]
extern "ExtismHost" {
    fn download_file(input: Json<DownloadFileInput>) -> Json<DownloadFileOutput>;
    fn exec_command(input: Json<ExecCommandInput>) -> Json<ExecCommandOutput>;
    fn get_env_var(key: String) -> String;
    fn host_log(input: Json<HostLogInput>);
    fn send_request(input: Json<SendRequestInput>) -> Json<SendRequestOutput>;
    fn set_env_var(key: String, value: String);
}
```

## Environment variables

The [`get_host_env_var`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/fn.get_host_env_var.html)
and [`set_host_env_var`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/fn.set_host_env_var.html)
functions read and write environment variables on the host, using the `get_env_var` and
`set_env_var` host functions respectively.

```rust
// Set a value
set_host_env_var("ENV_VAR", "value")?;

// Get a value (returns an `Option`)
let value = get_host_env_var("ENV_VAR")?;
```

Additionally, the [`add_host_paths`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/fn.add_host_paths.html)
function appends paths to the `PATH` environment variable.

```rust
// Append to path
add_host_paths(["/userhome/some/virtual/path"])?;
```

## Executing commands

The [`exec_captured`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/fn.exec_captured.html) (pipe)
and [`exec_streamed`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/fn.exec_streamed.html)
(inherit) functions execute a command on the host, using the `exec_command` host function. The
command must be available on `PATH` (or be a [virtual path](./virtual-paths.mdx) to an executable),
otherwise an error is returned. Commands run from the current working directory by default.

```rust
// Pipe stdout/stderr
let output = exec_captured("which", ["node"])?;

if output.exit_code == 0 {
    let path = output.stdout.trim();
}

// Inherit stdout/stderr
exec_streamed("npm", ["install"])?;
```

For full control, pass an `ExecCommandInput` to the
[`exec`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/fn.exec.html) function, which supports a
custom working directory (`cwd`), environment variables (`env`), additional `PATH` lookups
(`paths`), and a `shell` to wrap the command in.

```rust
exec(ExecCommandInput {
    command: "npm".into(),
    args: vec!["install".into()],
    cwd: Some(VirtualPath::new("/workspace/packages/app")),
    ..Default::default()
})?;
```

## Downloading files

The [`download_from_url`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/fn.download_from_url.html)
function downloads a file from a URL straight to a destination file on the host, using the
`download_file` host function. Unlike [sending a request](#sending-requests), the response body
is streamed to disk and never passes through WASM memory, which avoids allocating the entire file
in the guest. This is ideal for large artifacts, like archives and installers.

```rust
let temp_dir = VirtualPath::new("/moon/temp");
let output = download_from_url("https://some.com/url/to/file.tar.xz", temp_dir.join("file.tar.xz"))?;

output.file; // Virtual path written to
output.size; // Size in bytes
```

For full control, like custom headers, pass a `DownloadFileInput` to the
[`download`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/fn.download.html) function.

```rust
download(DownloadFileInput {
    url: "https://some.com/url/to/file.tar.xz".into(),
    destination: temp_dir.join("file.tar.xz"),
    ..Default::default()
})?;
```

## Sending requests

The [`fetch`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/fn.fetch.html)
function requests a URL on the host instead of from WASM, using the same HTTP client as the host CLI
(which supports `.netrc` credentials). It returns a response object with the raw body in bytes,
and the status code. Non-OK responses must be handled by you.

```rust
let response = fetch(SendRequestInput::new("https://some.com/url/to/fetch"))?;

if response.status == 200 {
    let text = response.text()?; // Or `response.json::<T>()?`
} else {
    // Error!
}
```

To simplify the handling of requests and responses, we provide the
[`fetch_bytes`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/fn.fetch_bytes.html),
[`fetch_json`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/fn.fetch_json.html), and
[`fetch_text`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/fn.fetch_text.html) functions, which
return an error for non-2xx responses and empty bodies.

```rust
let json: T = fetch_json("https://some.com/url/to/fetch.json")?;
```

Requests are sent with the `GET` method by default. To send a `POST` request instead, set the
`method` field on the input, or use the
[`SendRequestInput::post`](https://docs.rs/warpgate_api/latest/warpgate_api/struct.SendRequestInput.html)
constructor.

## Logging

The [`host_log!`](https://docs.rs/warpgate_pdk/latest/warpgate_pdk/macro.host_log.html) macro writes
messages to the host, using the `host_log` host function. It supports the same argument patterns as
`format!`, and messages support style tags like `<path>`, `<url>`, and `<id>`, which are colored in
the terminal.

- `stdout` and `stderr` write directly to the host's terminal.
- `debug`, `warn`, `error`, and `trace` write to host's logger, which are visible with the `--log`
  option.

```rust
host_log!(stdout, "Some message");
host_log!(stderr, "Some message with {}", "args");
host_log!(debug, "Processing <path>{}</path>", path);
```

If you want full control, like providing data/fields, use the input mode and provide a
[`HostLogInput`](https://docs.rs/warpgate_api/latest/warpgate_api/struct.HostLogInput.html).

```rust
let mut input = HostLogInput::new("Some message with data");
input.target = HostLogTarget::Stderr;
input.data.insert("file".into(), "example.txt".into());

host_log!(input, input);
```

Furthermore, the [extism-pdk](https://crates.io/crates/extism-pdk) crate provides macros for
writing level-based messages, which appear in the host's logs when the `--log` option is enabled.
These also support arguments.

```rust
debug!("This is a debug message");
info!("Something informational happened");
warn!("Proceed with caution");
error!("Oh no, something went wrong");
```

<Callout type="idea">
  To debug a plugin, run moon/proto with `--log trace` to see every host
  function call, and set the `MOON_DEBUG_WASM` or `PROTO_DEBUG_WASM` environment
  variable to also include Extism's own runtime logs.
</Callout>
