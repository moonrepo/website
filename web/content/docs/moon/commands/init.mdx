---
title: moon init
---

Initialize [moon](/docs/moon) in the current repository (or another destination), scaffolding the
minimum files required to run moon: a [`.moon/workspace.*`](../workspace) file and a `.gitignore` entry for
moon's internal cache and Docker directories.

The command first prompts you to confirm the destination to initialize into (skipped with `--yes`).
It then locates an existing config directory (either `.moon` or `.config/moon`, preferring the
latter if present) and, if configuration already exists there, prompts to confirm overwriting it
(skipped with `--force`, which also implies overwriting without asking).

Once confirmed, moon inspects the destination's Git repository to detect useful defaults:

- The upstream provider is detected from repository files — a `.gitlab` directory implies GitLab, a
  `bitbucket-pipelines.yml` file implies Bitbucket, and everything else falls back to GitHub — and
  written to the `vcs.provider` setting in [`.moon/workspace.*`](../workspace).
- The default branch is detected from the local Git checkout (or Git's global default when the
  repository has no commits yet) and written to the `vcs.defaultBranch` setting in
  [`.moon/workspace.*`](../workspace).

The generated [`.moon/workspace.*`](../workspace) also includes a commented out `projects` setting (pre-filled
with a `packages/*` glob example) that you must uncomment and adjust to match your repository's
project layout, as moon has no projects configured by default. Refer to the
[workspace](../workspace) fundamentals page for more information on these settings.

Lastly, `moon init` appends a `# moon` section to the destination's `.gitignore` file, ignoring
`.moon/cache` and `.moon/docker`, so moon's internal working files aren't committed to version
control.

This command is safe to re-run, and is commonly used to bootstrap a brand new repository, or to
add moon to an existing repository that doesn't have it configured yet.

```shell
# Initialize moon in the current directory
$ moon init

# Initialize moon in another directory
$ moon init ./app

# Skip prompts and accept all defaults
$ moon init --yes

# Overwrite an existing moon configuration
$ moon init --force
```

## Arguments

- `[DEST]` - Destination directory to initialize moon into. Defaults to `.` (the current working
  directory).

## Options

- `--force` - Overwrite existing configuration files without prompting for confirmation.
- `--minimal` - Initialize with minimal configuration and prompts.
- `--yes` - Skip all confirmation prompts and use default values.
