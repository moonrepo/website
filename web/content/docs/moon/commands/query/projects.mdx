Query information about every [project](../../project) in the project graph, and print the result
as a JSON array, like every other [`moon query`](../query) subcommand. Projects can be filtered either with the `[QUERY]` argument, using
[the query language (MQL)](../../advanced/query-lang), or with the individual `--option` flags below
— when `[QUERY]` is provided, it takes precedence and all filter options are ignored.

MQL is a small expression language for filtering projects and tasks with more precision than a
single regex flag allows. A statement is made up of `field operator value` comparisons — `=`/`!=`
for exact/negated matches (or `[a, b, c]` lists), and `~`/`!~` for glob-based matches — joined with
`&&`/`AND` or `||`/`OR`, and grouped with parentheses. Fields relevant to projects include
`project`, `projectId`, `projectAlias`, `projectSource`, `projectLayer`, `projectStack`, `language`,
`projectTag`/`tag`, and `task` (matches projects that own a task with that ID). See the
[query language docs](../../advanced/query-lang) for the full field and operator reference.

When no `[QUERY]` is given, the `--option` filters are applied instead, where every value is treated
as a case-insensitive regular expression matched against the relevant project field.

```shell
# List every project in the workspace
$ moon query projects

# Find projects whose ID matches "app"
$ moon query projects --id app
$ moon query projects "projectId~app"

# Find projects that own a `lint` or `build` task
$ moon query projects --tasks "lint|build"
$ moon query projects "task=[lint,build]"

# Find projects affected by changed files, including downstream dependents
$ moon query projects --affected --downstream deep
```

The output is a JSON object with a `projects` array (full [project](../../project) configuration
objects, including their tasks) and the resolved `options` that were used to produce them.

## Arguments

- `[QUERY]` - An [MQL statement](../../advanced/query-lang) to filter projects with. When provided,
  all filter options below are ignored.

## Options

### Affected

- `--affected` <TypeLabel type="boolean | string" /> - Filter down to only projects affected by
  changed files. When passed without a value, changed files are detected from the local working
  tree (or piped in via stdin, as produced by [`moon query changed-files`](./changed-files)); a
  string value further customizes the comparison, using the same syntax as the
  [`moon query affected`](./affected) `[BY]` argument.
- `--downstream` <TypeLabel type="none | direct | deep" /> - Include downstream dependents of
  the queried projects. Defaults to `none`. Can also be passed as `--dependents`. Requires
  `--affected` to also be passed.
- `--upstream` <TypeLabel type="none | direct | deep" /> - Include upstream dependencies of
  the queried projects. Defaults to `none`. Can also be passed as `--dependencies`. Requires
  `--affected` to also be passed.

### Filters

All values below are matched as case-insensitive regular expressions, and are ignored when
`[QUERY]` is provided.

- `--alias` <TypeLabel type="string" /> - Filter projects that match this alias.
- `--id` <TypeLabel type="string" /> - Filter projects that match this ID.
- `--language` <TypeLabel type="string" /> - Filter projects of this programming language.
- `--layer` <TypeLabel type="string" /> - Filter projects of this layer.
- `--source` <TypeLabel type="string" /> - Filter projects that match this source path.
- `--stack` <TypeLabel type="string" /> - Filter projects of this tech stack.
- `--tags` <TypeLabel type="string" /> - Filter projects that have a tag matching this pattern.
- `--tasks` <TypeLabel type="string" /> - Filter projects that have a task matching this pattern.
